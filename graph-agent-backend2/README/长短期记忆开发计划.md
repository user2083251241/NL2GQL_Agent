## 三、Agent长短期记忆实现详细指导

在当前主流的 LLM 智能体（Agent）系统中，"长短期记忆"通常借鉴人类认知模型，分为：

- **短期记忆（Short-term Memory）**：即**对话上下文（Conversation Context）**，保存最近几轮交互，用于维持对话连贯性。
- **长期记忆（Long-term Memory）**：即**可检索的历史知识或经验**，用于跨会话的知识积累、个性化、任务复用等。

下面结合当前项目的结构（Python + Agent 架构），给出**具体实现指导**。

### 一、短期记忆（Short-term Memory）

#### ✅ 目标
在单次会话中保留最近 N 轮对话（如用户提问 + Agent 回答 + 工具调用结果），作为 LLM 的上下文输入。

#### 🔧 实现方式
1. **数据结构**：使用 `list[dict]` 或 `deque` 存储消息历史。
   ```python
   # 示例格式
   messages = [
       {"role": "user", "content": "北京天气如何？"},
       {"role": "assistant", "content": "正在查询...", "tool_calls": [...]},
       {"role": "tool", "content": "北京晴，25°C"},
       {"role": "assistant", "content": "北京今天晴，25°C。"}
   ]
   ```

2. **存储位置**：
   - **内存中（会话级）**：适合 Web 请求场景，每次请求携带 `session_id`，服务端用字典缓存 `{session_id: messages}`。
   - **Redis 缓存**（推荐）：支持分布式、自动过期。
     ```python
     # 伪代码
     redis.setex(f"session:{session_id}", ttl=3600, value=json.dumps(messages))
     ```

3. **截断策略**（防止 token 超限）：
   - 使用 `tiktoken` 计算 token 数；
   - 超出时从最早的消息开始删除，直到满足 LLM 上下文窗口（如 8k tokens）。

4. **集成到 Agent**
   - 修改 `services/agents/agent.py`，在 `run()` 方法中传入 `messages` 历史；
   - 每次调用 LLM 前，拼接系统提示（system prompt）+ 历史消息 + 当前用户输入。

> ✅ **建议**：先在内存中实现（用 Python `dict`），后续替换为 Redis。

### 二、长期记忆（Long-term Memory）

#### ✅ 目标
跨会话存储用户偏好、常用工具、成功任务模式等，供未来检索使用。

#### 🔧 主流实现方式（基于 RAG 思想）

| 类型 | 描述 | 存储方式 | 检索方式 |
|------|------|--------|--------|
| **Episodic Memory** | 用户过往对话摘要 | 向量数据库（如 Chroma, FAISS, Milvus） | 语义相似度检索 |
| **Semantic Memory** | 提炼出的事实知识（如"用户喜欢咖啡"） | 图数据库 / MySQL / 向量库 | 关键词 or 向量检索 |
| **Procedural Memory** | 成功的任务执行流程（如"查天气→调用 weather_api"） | 结构化存储（JSON / DB） | 模式匹配 |

#### 🛠️ 推荐方案（轻量 + 可扩展）

##### 步骤 1：定义记忆写入时机
- 在 Agent 完成一次有效交互后（如回答被用户点赞，或任务成功），触发记忆存储。
- 对原始对话做**摘要**（可用 LLM 本身）：
  ```python
  summary_prompt = f"请用一句话总结以下对话的核心内容：{last_3_messages}"
  summary = llm_call(summary_prompt)
  ```

##### 步骤 2：向量化并存储
- 使用嵌入模型（如 `text-embedding-ada-002` 或开源 `bge-small`）生成向量；
- 存入向量数据库（初期可用 **Chroma**，无需部署；后期换 Milvus/Pinecone）。

##### 步骤 3：检索并注入上下文
- 每次新对话开始时，用当前用户问题向量检索 top-k 相关记忆；
- 将记忆作为额外上下文插入 prompt：
  ```text
  你是一个智能助手。以下是与该用户相关的历史信息：
  - 2024-05-01: 用户偏好查看图表而非表格。
  - 2024-05-03: 用户常查询"某公司供应链关系"。

  当前问题：...
  ```

#### 💡 在项目中的落地建议

1. **新建模块**：
   ```
   modules/
   └── memory/
       ├── __init__.py
       ├── short_term.py   # 短期记忆（Redis 或内存）
       └── long_term.py    # 长期记忆（Chroma + Embedding）
   ```

2. **依赖**：
   - 短期：`redis`（可选）、`tiktoken`
   - 长期：`chromadb`、`sentence-transformers`（或调用 OpenAI embedding API）

3. **集成到 agent_service.py**：
   ```python
   class AgentService:
       def handle_query(self, user_id, session_id, query):
           # 1. 加载短期记忆
           short_mem = self.short_memory.get(session_id)
           # 2. 检索长期记忆
           long_mem = self.long_memory.retrieve(user_id, query)
           # 3. 构造完整 prompt
           full_context = build_prompt(system_prompt, long_mem, short_mem, query)
           # 4. 调用 agent
           response = self.agent.run(full_context)
           # 5. 更新短期记忆
           self.short_memory.append(session_id, query, response)
           # 6. （可选）触发长期记忆写入
           if should_save_memory(response):
               self.long_memory.save(user_id, summarize(...))
   ```

### 三、注意事项

1. **隐私与安全**：用户记忆需脱敏，提供清除接口；
2. **成本控制**：长期记忆的 embedding 和摘要会增加 LLM 调用次数；
3. **评估机制**：并非所有对话都值得记忆，可设计"记忆价值评分"（如用户反馈、任务复杂度）；
4. **游客 vs 用户**：游客不保存长期记忆，仅保留短期会话（且会话结束后清除）。
